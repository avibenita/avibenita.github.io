# Statistico demo inputs

Add **Load demo data** to every Statistico module input view. Use the supplied synthetic data and preset scenarios. A user with an empty workbook should be able to load the demo, see the populated role assignments or form fields, and use the standard Run, Analyze, Calculate, Preview, or equivalent action.

## Inspect first

1. Trace the task-pane launch registry and every reachable input route. Inventory the active module IDs, modes, current demo helpers, input source pipeline, type and role assignment rules, grouping controls, and host-specific views. Cover calculator children and nested input modes as well as top-level menu links. Use the screenshots for the 24 listed modules and the calculator section of `catalog.json` as the starting inventory. Record the actual route and mode mapped to each demo in the implementation report.
2. Reuse the existing input components, local-data adapters, grouping and type validation, and task-pane/dialog transport. Treat the catalog’s IDs, descriptive roles, settings, and names as fixture metadata. Translate them into the active input contract. For each live input view, resolve its compatible fixture or preset before enabling the demo action. Where the repository has an additional active input or calculator mode, supply a module-specific fixture or preset with a meaningful grouping field and add it to the inventory. Omit disabled menu entries from the route coverage check until they become active.
3. Verify the input contract for weighted contingency cells, study effect scales, Gage R&R design modes, Process Optimization, Scale Reliability, Publication Tables and EzPaste before mapping their fixtures. Keep existing built-in examples linked to these same assets where the roles and story match.

## Load and reset

1. Put **Load demo data** near the source or input controls as a secondary action. Provide **Load demo inputs** on scalar-only forms if that wording fits the existing UI. Keep a single recommended example on the primary action. Use the existing scenario or input-mode selector for alternatives and keep the active mode unless the user explicitly chooses another.
2. On click, resolve the active module and mode, load the embedded asset or preset, and validate its headers, types and required roles. Commit the new source and role assignments together. Show **Demo data · [scenario name]** or **Demo inputs · [scenario name]** next to the source. Populate the relevant group selector or preset choices. Leave the input view open for review. Use the normal primary action to run or preview the configured example. In a calculator that already recalculates on edit, apply the preset as one transaction through its usual recalculation path.
3. Store the previous source selection and draft input state using the existing state model. Show **Return to my data** or **Return to my inputs** when there is a prior draft. Restore it, including source, field roles, settings and selection. For an empty prior state, return to the standard empty input state. On navigation to a different route, scope demo state and responses to their own input view. Ignore any response that arrives after its view or active load has changed. Repeated clicks must be safe.
4. Keep fixture data in the app’s supported temporary source when it can consume local rows. If a module requires native Excel objects or a worksheet range, use its existing sample-sheet/object workflow or a clearly named noncolliding **Statistico Demo** sheet. Reuse only app-owned, unmodified demo artifacts when safe. Preserve user worksheets, ranges, objects and existing outputs. For EzPaste, disclose the sheet creation in the action or its adjacent helper text and prepare the actual table and chart from the supplied rows. Use the module’s normal preview and export controls for subsequent actions.
5. On loading, show the existing pending state. If demo loading or role validation fails, keep the current source and draft, clear pending state, and show **Couldn’t load demo data. Try again.** Use the corresponding **demo inputs** wording in scalar forms. Keep existing run and validation rules. Pass the demo label through to previews and results where the module can show the input source.

## Data and grouping

- Each CSV names a categorical `group_field` in `catalog.json`. Default to pooled results and surface the group choice where group analysis is supported. Use the existing table, color, series, stratification, subgroup, or filter role as appropriate. Keep grouping available independently of outcome, analysis feature, study effect, treatment or comparison factor, and subject ID. Use a selected group filter where the method requires an independent fit, such as defaulting to Bench A for the crossed Gage R&R study.
- For cluster demos, use only the numeric fields listed under `features` for fitting. `market` can color or filter the results. For PCA and Factor Analysis, use the listed numeric measures and items. For Split Index, `renewal_intent` is the binary split and `purchase_channel` is the additional grouping field.
- For Independent Groups, use the preselected training-level subset in two-group mode and all three levels in the multiple-group mode. `site` is an additional grouping field. For paired and repeated data, keep visits in the supplied order and keep `program` at participant level. The long and wide files contain the same measurements. Mixed Models preserves subject IDs and omitted intermediate visits. Use `program` as a fixed effect in the pooled fit. Within a single program, build a valid model using the remaining varying predictors.
- Select categorical references and event levels explicitly where the form supports them. Use Contingency `frequency` through the frequency path. If a route supports categorical rows only, expand the fixture at load by its nonnegative integer frequency and drop the frequency field from analysis. For meta-analysis, keep one row per study. Choose binary counts, continuous summaries, or effect and SE according to the form. The effect fixture is on the log risk-ratio scale. Pool on that scale and exponentiate only for ratio-scale reporting. `study_setting` is a subgroup label.
- Process Optimization has crossed factor settings, with each combination replicated twice within each line, and two measured responses. Use only supported factor, response, and objective roles. Offer cycle time as another response where the current input permits one response. Keep optimization searches within supported observed ranges for the demo. In Process Capability, use `diameter_mm` and specs 10, 20 and target 15. `line` is the comparison group. `subgroup_id` describes consecutive sets of five within a line for a route that uses rational subgroups. Preserve observation order for control charts. Reuse this data for measurement-based Quality Control views when their worksheet contract fits and retain a single compatible line when charting a single process stream.
- For Reliability, the first six confidence items are scored from 1 to 5. The optional avoidance item is raw and needs `6 − raw` if included. Use the existing reverse-item control or omit that item from the default selection. For Prepare Data, preserve leading and trailing spaces, blanks, mixed text and numeric values, and duplicate rows at load so the cleaning actions can be demonstrated.
- For Publication Tables, default to the baseline table by study arm where available. For an input that consumes fitted model output, fit the bundled linear demo through the normal path and pass its actual result. For EzPaste, use a table of quarterly summaries and an Excel chart with quarter categories and one series per region. Selecting a demo object should behave like selecting an ordinary export object.
- Scalar calculators use the categorical field as the scenario choice, one input set at a time. Route each preset by its method and solve mode. Translate fractions to percentages where required, handle geometric support conventions explicitly, and convert rate or scale units to the current form. The power presets give planning assumptions. Adopt the form’s supported parameterization and method, preserving units and the meaning of total N, per-group N, pairs, or subjects. Where a preset’s planning assumption cannot be represented directly, choose a compatible example for that live mode and record the mapping. The Simulation seed applies only if supported. Keep typed and worksheet Contingency and the two Capability entry points wired to their respective modes.

## Acceptance checks

1. Starting with an empty workbook, open every active input route and mode received from the task pane or hub. One click loads a compatible demo. The normal primary action is available and completes in supported hosts. Confirm the demo control and source label fit the narrow task pane and keyboard focus reaches both the demo action and the primary action.
2. Load worksheet data, change a role and an analysis setting, then load a demo and return to the prior source. The original data, role and settings return. Repeat loading and switch routes during loading. Simulate an unavailable or invalid asset and confirm the previous input stays usable. Verify that an existing worksheet and same-named chart are preserved.
3. Compare the group options, row counts, and key results with `catalog.json` and `reference_checks.json`. Example anchors include Linear Regression’s most influential store `S031` with region in the model, a 2×2 pooled risk ratio of approximately 0.617 with the specified reference and event, and Reliability alpha near 0.842, rising to 0.884 when item 6 is omitted. Use the reference method attached to each metric and the app’s own results where settings differ.
4. In Process Capability, Line A has 0 of 100 observed outside spec. Line B has 3 of 100, with 1 below LSL and 2 above USL. Switching the histogram from 9 to 10 bins must preserve those counts, the identity of any actual-value markers, and the calculated capability metrics. Show model-based expected PPM separately from the observed count. This is a regression check on the demo and existing histogram path.
5. Verify that the correct data and roles load for each layout or mode: two and three independent groups, wide and long repeated measures, supported study input types, a grouped Pareto result, a complete crossed Gage R&R bench, typed calculator input, and EzPaste preview of a real table and chart. For calculators, verify the mapped field values, units and valid output on every registered route. Run the ordinary user-data and manual-entry flows after the shared changes.
